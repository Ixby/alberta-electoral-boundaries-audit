**Rules for wrappers.** Registered scripts are frozen and are not edited. Each wrapper imports the registered module, overrides only the named constants or the VA-file argument, no-ops the audit logger (`_log_run`, which appends to `data/outputs/script_run_audit.jsonl`, an existing file this rehearsal may not modify), and calls the module's own entry point. Where a module's entry point cannot be called as filed (stated per step), the wrapper calls the module's own functions and says so. The run record (`OUT/README.md`) states every deviation.

**Memory rule.** About 2 GB free at start. Before every step that loads a 1,010,000-row CSV, free RAM is read; the loads use `usecols` (four columns, about 32 MB). No MCMC chain is started.

**Scoring step that produces the map's all-ballots scores (the file `data/outputs/iap_assembled_phase4c.json` is the election-day version).** `iap_assembled_phase4c.json` was produced by `analysis/scripts/phase4c_canonical_attribution.py --majority … --output … --map-key iap_2026_assembled` (Step C step 1; `score_candidate()` calls `mcmc_ensemble.build_va_graph(verbose=False)` with no VA path, i.e. the election-day file, then `score_exogenous_map`). The all-ballots equivalent is written by wrapper `w01`, which calls the same two functions with `va_path=` the all-ballots file.
