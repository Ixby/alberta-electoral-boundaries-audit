Alberta Electoral Boundary Audit

Privacy & Data Retention Policy

Effective: 2026-11-03 · Maintained by Will Conner

Overview

This tool is a public-interest audit of Alberta's 2025–26 electoral boundary commission process. It is not a commercial product and runs no advertisements. This page explains what the analytics measure, what they never collect, and why none of it can be tied back to you. It also says what the feedback form keeps.

The short version: the site uses cookieless, aggregate analytics. There is no tracking cookie, no advertising, no cross-site profiling, and no identifier that follows you. Because the analytics store nothing personal, there is no consent banner to click through — the privacy protection is built into how the measurement works, not bolted on as a prompt.

How the analytics work

When a page loads or you interact with the map, the site sends a small, anonymous event to a counting service we run. Each event is just the name of what happened — for example, "page viewed" or "district selected" — plus a few coarse details about the action. The event carries no name, no email, no account, and no identifier stored on your device.

To count how many distinct people visited on a given day without identifying anyone, the counting service combines your network address and browser type and runs them through a one-way cryptographic hash together with a secret that changes every day. The result is a short code that lets us tell two visits apart within a single day, and nothing more. The original address is never stored — only the hash is. Because the secret rotates daily, the same visitor produces a different code tomorrow, so no one can follow a visitor across days. When a new day's secret is made, the old one is deleted. After that, no one can work backwards from a code to a person.

We are interested in the picture that visitors paint as a group — which findings get read, which maps get opened, which districts draw attention. We are not interested in you specifically, and the measurement is built so that "you specifically" is not something the data can express.

What is measured

The analytics record aggregate, anonymous events such as:

  • Page views
  • How far down a page people scroll, in coarse bands (25%, 50%, 75%, 100%)
  • Roughly how long the page was actively on screen, in coarse time buckets
  • Which finding sections come into view as people read
  • Which maps are opened in the explorer, and which districts are selected
  • Which map layers are turned on or off, and roughly how far in people zoom
  • Which points of interest or report links are opened
  • A coarse picture of your setup — screen-size band (such as phone, tablet, or desktop), form factor, and browser family (such as Chrome, Safari, or Firefox). The analytics never store your exact screen dimensions or full browser identification string.
  • A one-time snapshot of how the map explorer performed when it first drew — for example, the load time in coarse bands and a rounded memory figure. This helps us tell whether the explorer is fast enough on real devices. The numbers are deliberately banded, not exact, so they describe a device class rather than a device.

Each of these is stored as a separate event that carries no identifier except that day's code, and is reported only in aggregate. There is no per-person profile, no session replay, and nothing that links one day's visits to the next. We see totals and distributions, not people.

What the analytics never collect

The analytics collect no name, no email and no account. No advertising identifier. No stored IP address — your network address is hashed with a daily-rotating secret and immediately discarded; only the daily code is kept, and it changes every day. No raw browser fingerprint. No cross-day or cross-site identifier. No precise location. No cookie or browser-storage identifier that marks you as a returning visitor for analytics purposes.

What GitHub Pages collects

This site is hosted on GitHub Pages. GitHub's servers automatically log basic request details when any page loads — your IP address, browser type, referring page, and timestamp. We do not receive or control these logs; they are governed by GitHub's Privacy Statement. We have no relationship with GitHub beyond hosting. The analytics described above run separately and never store your IP address.

Share links

The map explorer has a Share feature. It writes your current map view — which maps are on, which overlays are showing, roughly where your viewport sits — into the page's web address, and Copy link puts that address on your clipboard so you can send it to someone. The link describes a map configuration, not a person. Two people who arrive at the same view independently get the same link; that is expected, and nothing in it ties them together.

Because the view lives in the address, it goes wherever web addresses go: into your browser history, and to GitHub's servers when someone opens the link. The analytics never see it. They record only which page was viewed, not the view in its address.

Nothing is saved when you share. The link carries the whole view itself, so no database is needed to make it work, and we keep no record of who shared what. Copying a link sends nothing to the analytics.

Cookies and browser storage

The analytics use no cookie and no browser-storage identifier. Nothing about the measurement marks you as a returning visitor.

The site does set one small functional cookie to remember your own preferences between visits. It is not used for analytics or tracking, and it never leaves your browser in readable form. It stores:

  • Colour theme — dark or light, if you changed it
  • Intro dismissed — so the map introduction doesn't repeat
  • Current map view — so your last view is restored if you come back within ten minutes
  • Browser language — so the site can show your preferred language

This cookie holds only the preferences above — no personal or identifying information. Its contents are scrambled with a key that ships inside the page, so the stored value is not human-readable; because that key is public, treat this as tamper-resistance rather than true secrecy. It is sent only over HTTPS, is never shared with other sites, and expires one year after it was last saved. You can remove it at any time by clearing your cookies. The site is served as static files, so nothing on the server side reads it. Your colour theme is also mirrored to your browser's local storage so the correct theme can be applied instantly on load, before anything flickers; that value too is purely functional and never sent anywhere. If you choose a language, local storage keeps that choice the same way.

Data retention

The analytics records are anonymous by construction: the only identifier in them is the daily code described above. They are stored on infrastructure hosted in Canada (ca-central-1) and kept as research data. If we ever found that a record contained identifying information — which the design is built to prevent — we would delete it within 30 days.

Your choices

Because the analytics collect nothing personal, there is nothing to opt out of and no consent prompt to manage. If you would still prefer to send no analytics events at all, a content blocker or a browser that blocks the request to the counting service will stop them, and the site will work exactly the same. You can also clear the functional preferences cookie at any time through your browser.

Contact

Will Conner — independent research, not affiliated with or endorsed by any institution.

The feedback form is separate from the analytics. When you send a message, the page sends your message, your name and email only if you give them, the language you were reading in, the address of the feedback page, and the address of the page you came from if your browser reports one. As with any web request, your browser also sends its identification string and your network address. To limit repeat sending, the service checks a hash of your network address made with a daily-changing secret. Messages are kept on the same Canadian infrastructure as the analytics records. Questions, corrections, and deletion requests, including deletion of a message you sent: please use the feedback form. Requests are answered within 10 business days.

Policy updates

When this policy changes, the effective date at the top is updated and the change is committed to the public git repository. The commit history is the changelog. Any change that expands what is collected is noted in the commit message.
