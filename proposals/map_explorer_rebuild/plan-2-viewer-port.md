# deck.gl MapExplorer Port — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Replace the production SVG MapExplorer with a native deck.gl explorer (ported from the validated `viewer/static/spike/` prototype), mounted in the existing `#zoom-overlay`, with full feature parity — district-name search and Supabase telemetry — and the SVG explorer retained as a non-WebGL fallback.

**Architecture:** A lazy-loaded deck.gl component (`DeckExplorer.svelte`) backed by three pure-logic TS modules (`loader`, `layers`, `search`) plus `telemetry`. deck.gl is dynamically imported under a `browser` guard (proven to survive adapter-static prerender). Data is the spike's binary LOD-tile pipeline, served base-path-safe from `viewer/static/mapdata/`. On overlay open, a WebGL check chooses deck.gl vs the existing SVG `mapEngine`.

**Tech stack:** SvelteKit 2 + Svelte 5 (runes) + adapter-static; `@deck.gl/core` + `/layers` + `/extensions` @9.0.36 (installed); `@supabase/supabase-js` (existing); vitest + happy-dom (existing).

**Proven by the spine (do not re-investigate):** native deck.gl modules import & render; adapter-static build/prerender survives the dynamic import; `${base}` fetch resolves tiles under `/alberta-electoral-boundaries-audit/`; the `.bin` decode is correct (4716 VA fills rendered). Open caveat only: pass an explicit canvas `width`/`height` defensively (the `parent`-only path is untested on a live server).

**Verification philosophy (per advisor):** TDD for pure logic (bin decode, LOD math, agreement grouping, search index, telemetry payloads). For rendering, use the thin-slice + user-eyeball + the existing province-wide coverage check — do NOT force TDD onto "does the map look right." Commit after each task.
